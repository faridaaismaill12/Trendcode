Homomorphic encryption

Encryption that lets a server compute on your data without ever being able to read it.

🔐 Cryptography Advanced 3 min read

01In plain words

Normally, to process data you must first decrypt it, and whoever does the processing can see everything. Homomorphic encryption (HE) is like a locked glovebox: you can put your hands in and work on what's inside, but you can never take it out or see it. A cloud server can add, multiply or even run a machine-learning model on encrypted numbers, and when you decrypt the result it's exactly what you'd have got on the plain data.

02Why it matters

Encryption traditionally protects data at rest and in transit, but not in use. HE closes that gap, so sensitive data like medical records, financial data or private queries can be analysed by a third party that never sees it. That's a big deal for privacy laws, outsourcing and cloud AI.

03How it works

  1. Encrypt with structure. Ciphertexts are built so that mathematical operations on them correspond to operations on the hidden values. Most modern schemes are lattice-based.
  2. Operate. Adding two ciphertexts gives an encryption of the sum; multiplying gives the product. Any computation can be built from additions and multiplications.
  3. Manage the noise. Each ciphertext carries a little random noise for security, and it grows with every operation, multiplication especially. Too much noise and decryption fails.
  4. Bootstrap. Craig Gentry's 2009 breakthrough showed how to “refresh” a ciphertext by homomorphically running the decryption itself, resetting the noise. This made fully homomorphic encryption (FHE) possible.
  5. Choose a scheme. BFV and BGV for exact integers, CKKS for approximate real numbers (great for ML), TFHE for fast operations on bits.

04Real-world example

Checking leaked passwords privately

Microsoft Edge's Password Monitor uses homomorphic encryption to check your saved passwords against a database of breached credentials, without Microsoft learning your passwords. Apple uses HE for features such as Live Caller ID Lookup, so the server answers a query it can't read. Hospitals and banks are piloting HE to run joint statistics on data neither may share.

05Advantages & limitations

Advantages

  • Data stays encrypted end to end, even during processing.
  • No need to trust the cloud provider or the hardware.
  • Built on lattice problems, so it's believed to be quantum-resistant.

Limitations

  • Slow: computations can be thousands to millions of times slower than on plain data, depending on the task.
  • Ciphertexts are much larger than the data they hold.
  • Programs must be rewritten as fixed circuits. Data-dependent branching and loops are hard.
  • Expertise-heavy: picking parameters wrongly can break security or correctness.

06Security & privacy implications

  • HE protects confidentiality, not integrity. A malicious server could compute the wrong function, so pair it with verification when that matters.
  • Results eventually get decrypted. Make sure outputs themselves don't leak more than intended.
  • Access patterns and timing can leak information unless the protocol is designed to hide them.
