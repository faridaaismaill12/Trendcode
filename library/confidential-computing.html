Confidential computing

Hardware-protected “enclaves” that keep data encrypted even while a computer is processing it.

🔐 Cryptography Intermediate 3 min read

01In plain words

Encryption usually protects data while it's stored or travelling, but the moment a program uses it, it sits unprotected in memory where a compromised operating system, a rogue administrator or the cloud provider could peek. Confidential computing uses special CPU features to create a sealed room, a trusted execution environment (TEE), where code runs on decrypted data that nothing outside the room can see.

02Why it matters

It makes it possible to process sensitive data on infrastructure you don't control, like a public cloud, a partner's servers or an AI provider, while keeping that data hidden from them. It's increasingly used for private AI, multi-party data collaboration and protecting cryptographic keys.

03How it works

  1. Isolate. The CPU creates a protected region: an enclave inside an app (Intel SGX) or an entire virtual machine (AMD SEV-SNP, Intel TDX, Arm CCA).
  2. Encrypt memory. Data leaving the CPU for RAM is automatically encrypted with keys that never leave the processor. The OS and hypervisor see only ciphertext.
  3. Attest. Before sending secrets, a remote party asks the hardware for a signed attestation report proving exactly which code is running inside a genuine TEE.
  4. Release secrets. Only if attestation checks out are keys or data provisioned into the enclave.

04Real-world example

Private contact discovery and private AI

Signal uses Intel SGX enclaves so its servers can match your contacts against registered users without Signal itself learning your address book. Major clouds offer “confidential VMs”, and Apple's Private Cloud Compute (2024) applies similar ideas so its servers process AI requests that even Apple staff can't inspect.

05Advantages & limitations

Advantages

  • Protects data in use, the missing piece of end-to-end protection.
  • Runs normal code at near-native speed, unlike homomorphic encryption.
  • Remote attestation gives verifiable evidence of what code handles your data.

Limitations

  • You must trust the CPU vendor's hardware, firmware and attestation service.
  • Side-channel attacks have repeatedly broken TEEs. Foreshadow (2018) and Plundervolt (2019) both extracted secrets from SGX.
  • Some performance overhead and extra operational complexity, especially around attestation and updates.

06Security & privacy implications

  • Treat TEEs as one strong layer, not a magic box. Keep firmware patched and combine with other controls.
  • Attestation is only meaningful if someone actually verifies the measured code and keeps the list of trusted versions current.
  • Code running inside the enclave can still have ordinary bugs that leak data.
