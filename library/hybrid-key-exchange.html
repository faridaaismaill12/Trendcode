Hybrid key exchange

Combining a classical and a post-quantum algorithm so a connection stays safe if either one holds.

🔐 Cryptography Intermediate 3 min read

01In plain words

When you're not sure which of two locks is stronger, fit both: a burglar has to defeat each one. Hybrid key exchange does this for encrypted connections. It runs a trusted classical method (like X25519) and a new post-quantum one (like ML-KEM) side by side and mixes their outputs into one key. An attacker must break both.

02Why it matters

Post-quantum algorithms are new. They might have undiscovered weaknesses, or buggy implementations. Classical algorithms are well understood but vulnerable to future quantum computers. Hybrid gives you the best of both during the transition years, and it's how the post-quantum rollout is actually happening on the internet today.

03How it works

  1. Two key shares. The client sends both a classical key share (for example X25519) and a post-quantum one (an ML-KEM encapsulation key).
  2. Two secrets. The server responds to both, and each side ends up with two shared secrets.
  3. Combine. Both secrets are fed together into a key-derivation function. The resulting session key is secure as long as at least one input secret is secret.
  4. Use as normal. The rest of the connection (for example AES-GCM encryption) is unchanged.

04Real-world example

X25519MLKEM768 on the web

Chrome turned on hybrid post-quantum key exchange by default in 2024, now using X25519MLKEM768, and Cloudflare and other large providers support it, so a large share of HTTPS traffic is already hybrid. OpenSSH made a hybrid (sntrup761 + X25519) its default in 2022 and switched to ML-KEM + X25519 by default in 2025.

05Advantages & limitations

Advantages

  • Protects against both future quantum attacks and unknown flaws in new algorithms.
  • Satisfies compliance needs that still require classical, certified algorithms.
  • Can be deployed today with modest overhead.

Limitations

  • Larger handshakes: the extra kilobyte or so pushed some TLS ClientHello messages beyond one packet, which broke a few badly built middleboxes.
  • More code and more combinations to test and maintain.
  • A transitional design. Eventually systems may move to pure post-quantum.

06Security & privacy implications

  • The combiner must be designed properly. Simply XOR-ing secrets can lose the “secure if either holds” guarantee in some settings.
  • Hybrid key exchange protects confidentiality now, but authentication (certificates and signatures) also needs a post-quantum migration.
