Quantum-resistant encryption

The new families of algorithms designed to stay secure even against large quantum computers.

🔐 Cryptography Beginner 3 min read

01In plain words

Today's internet locks (RSA and elliptic-curve cryptography) are built on maths problems that a big enough quantum computer could solve quickly. Quantum-resistant (or post-quantum) encryption swaps those problems for different ones that no known quantum algorithm can crack. The clever part: it runs on ordinary computers and phones. You don't need any quantum hardware to use it.

02Why it matters

Attackers can record encrypted traffic today and decrypt it later once quantum computers mature (“harvest now, decrypt later”). Replacing cryptography across every browser, server, phone and device takes many years, so the migration has to start well before the threat arrives. Governments have set target dates in the early 2030s.

03How it works

  1. Pick new hard problems. Instead of factoring, these schemes use problems such as finding short vectors in a high-dimensional lattice, decoding random error-correcting codes, or inverting hash functions.
  2. Key encapsulation (KEM). To agree on a key, one side encapsulates a random secret using the other's public key. Only the private key can recover it. NIST standardised ML-KEM (FIPS 203) for this.
  3. Signatures. To prove authenticity, NIST standardised ML-DSA (FIPS 204, lattice-based) and SLH-DSA (FIPS 205, hash-based), with Falcon (FN-DSA) to follow.
  4. Backups on different maths. In 2025 NIST also selected HQC, a code-based KEM, so the world doesn't depend on a single family of problems.
  5. Deploy alongside classical crypto. During the transition, most systems combine a post-quantum algorithm with a classical one (hybrid mode).

04Real-world example

Your messages are probably already protected

Signal added post-quantum protection (PQXDH, using Kyber) in 2023, Apple's iMessage moved to its PQ3 protocol in 2024, and Chrome and Cloudflare now use a hybrid of X25519 and ML-KEM by default for TLS. If you use an up-to-date browser, much of your web traffic already has a post-quantum layer.

05Advantages & limitations

Advantages

  • Runs on existing hardware, so it can be rolled out with software updates.
  • Standardised after an eight-year public competition with worldwide cryptanalysis.
  • Lattice schemes are fast: ML-KEM is competitive with, and sometimes faster than, elliptic-curve key exchange.

Limitations

  • Keys, ciphertexts and signatures are bigger: an ML-KEM-768 public key is 1,184 bytes and an ML-DSA-65 signature is 3,309 bytes, versus tens of bytes for elliptic curves.
  • The algorithms are younger, with fewer years of attack attempts. One finalist candidate (SIKE) was broken in 2022.
  • Migration is a huge inventory and engineering effort, especially for embedded and long-lived devices.

06Security & privacy implications

  • Implementation bugs and timing side channels are a bigger near-term risk than mathematical breaks. Use well-reviewed libraries, never home-made code.
  • Hybrid deployment hedges against an unexpected break in a new algorithm.
  • Prioritise data with a long secrecy lifetime (health, state, financial records), because that's what harvest-now-decrypt-later targets.
