AI model security

Protecting AI systems, from training data to model weights to the live application, against attack and misuse.

🤖 AI Intermediate 3 min read

01In plain words

An AI model is software, but an unusual kind: its behaviour comes from data rather than hand-written rules, and it responds to natural language that anyone can type. AI model security covers all the new ways that can go wrong: tricking the model, stealing it, poisoning what it learns, or using it to leak secrets. It also covers the ordinary software security of everything around it.

02Why it matters

AI is being plugged into email, customer data, code repositories and business decisions. A compromised or manipulated model can leak confidential data, give dangerous advice, or take harmful actions through connected tools. Attackers have noticed, and regulators increasingly expect AI risks to be managed.

03How it works

  1. Map the lifecycle. Consider risks at each stage: data collection, training, model storage and distribution, deployment, and use.
  2. Protect data and weights. Control who can change training data, sign and verify model files, and keep weights encrypted with strict access control.
  3. Harden the application. Treat prompts and model outputs as untrusted, add input and output filtering, and limit what tools the model can use.
  4. Test like an attacker. Red-team for jailbreaks, prompt injection, data leakage and harmful outputs before and after launch.
  5. Monitor. Log interactions, watch for abuse patterns and unusual query volumes, and have an incident response plan.

04Real-world example

Leaks, malicious models and stolen behaviour

In 2023, Samsung restricted employee use of public chatbots after staff pasted confidential source code into one, an example of data leakage through AI use. In 2024, security researchers found models on public model hubs that ran malicious code when loaded, because they used Python's unsafe “pickle” file format. Safer formats like safetensors exist for exactly this reason.

05Advantages & limitations

Advantages

  • Good AI security builds user and regulator trust.
  • Most controls (access control, logging, least privilege) reuse proven security practice.
  • Frameworks such as the OWASP LLM Top 10, MITRE ATLAS and the NIST AI RMF give structure.

Limitations

  • No complete defence exists yet against jailbreaks or prompt injection.
  • Models are hard to audit: behaviour emerges from billions of parameters.
  • The field moves fast, so threat models age quickly.

06Security & privacy implications

  • Model extraction: attackers can approximate a model by querying it heavily, so rate-limit and watch for scraping.
  • Supply chain: only load models and datasets from trusted sources, verify hashes and signatures, and avoid formats that execute code on load.
  • Privacy: models can memorise and regurgitate training data, so filter sensitive data before training and consider differential privacy.
