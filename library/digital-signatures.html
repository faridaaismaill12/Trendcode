Digital signatures

The cryptographic proof that a message, file or update really came from who it claims, unchanged.

🔐 Cryptography Beginner 3 min read

01In plain words

A handwritten signature is easy to forge and says nothing about whether the page was changed afterwards. A digital signature is far stronger. It's created with a private key only the signer holds, and anyone can check it with the matching public key. If even one bit of the signed data changes, the check fails.

02Why it matters

Signatures quietly hold the digital world together. They prove that software updates come from the real vendor, that a website's certificate is genuine, that a bank instruction wasn't tampered with, and that code commits came from a particular developer. Without them, anyone could impersonate anyone.

03How it works

  1. Key pair. The signer generates a private key (kept secret) and a public key (shared freely).
  2. Hash. The message is hashed to a short, fixed-size fingerprint.
  3. Sign. The hash is processed with the private key to produce the signature.
  4. Verify. Anyone recomputes the hash and checks it against the signature using the public key. A match proves integrity and authenticity.
  5. Trust the key. A certificate, issued by a certificate authority or a web of trust, binds the public key to a real-world identity.

04Real-world example

Every software update you install

When your phone or laptop installs an update, it first verifies the vendor's signature. Malware can't push a fake update without the vendor's private key. The same mechanism signs app-store apps, TLS certificates for every HTTPS site, and Git commits on GitHub.

05Advantages & limitations

Advantages

  • Provides integrity, authenticity and non-repudiation: the signer can't plausibly deny signing.
  • Verification needs only public information.
  • Modern schemes like Ed25519 are fast with tiny signatures (64 bytes).

Limitations

  • Everything hinges on protecting the private key. A stolen key lets attackers sign anything.
  • RSA and ECDSA signatures will be broken by large quantum computers, so a migration to ML-DSA and SLH-DSA is under way.
  • Signatures don't provide confidentiality: signed data is still readable.
  • Needs a working public-key infrastructure to know which key belongs to whom.

06Security & privacy implications

  • Implementation mistakes are deadly. In 2010, Sony's PlayStation 3 reused the same random number in ECDSA signatures, which let hackers compute the private signing key.
  • Use hardware security modules (HSMs) or secure enclaves to keep signing keys out of reach, and plan for key rotation and revocation.
  • Long-lived signatures (legal documents, firmware roots of trust) should move to post-quantum or hash-based schemes first.
